# ML Methodology

## Chennai Metropolitan Region Traffic Simulation — Machine Learning Pipeline

### Overview

The ML pipeline trains supervised regression models to predict hourly traffic volume (`vehicle_count`) per zone-road-hour combination. All training data is synthetic — generated by the Chennai simulation engine (`scripts/build_pipeline.py`).

---

## Dataset

| Property | Value |
|---|---|
| Generation period | 2025-01-01 to 2025-12-31 (12 months) |
| Temporal resolution | Hourly |
| Zones | 17 Chennai Metropolitan Region zones |
| Roads | 34 (2 per zone) |
| Total rows (before lag drop) | ~297,840 |
| Rows after feature engineering | ~297,024 |
| Target variable | `vehicle_count` (vehicles/hour per road) |
| Data type | Synthetic / Research-Grounded |

## Train / Validation / Test Split

**Method: Chronological (no shuffling)**

```
Train:      70%  (Jan 2 – ~Sep 13, 2025)
Validation: 15%  (~Sep 13 – ~Nov 7, 2025)
Test:       15%  (~Nov 7 – Dec 31, 2025)
```

**No data leakage:** All lag and rolling features are computed strictly on past values. The global sort is by timestamp (not by zone-road) so the split boundary is a strict chronological wall.

## K-Means Behaviour Clustering

**Purpose:** Identify population-level mobility patterns per zone.
**Input:** Mean hourly vehicle count profile per zone × weekday/weekend.
**k=7:** Produces 7 interpretable mobility pattern classes.

**Privacy:** Analysis is at the zone level — no individual trajectories or personal data.

**Interpreted patterns:**
- Office / IT Commuter Pattern
- School Zone Mobility Pattern
- Shopping / Evening Demand Pattern
- Intercity / Transit Hub Pattern
- Industrial Shift Pattern
- High-Volume Commuter Corridor
- Residential Mixed Pattern

---

## Isolation Forest (Anomaly Detection)

**Purpose:** Detect unusual traffic events in the simulation.
**Contamination:** 0.02 (2% expected anomaly rate)
**Window:** Last 60 days of simulation data
**Features used:** `vehicle_count`, `hour`, `day_of_week`, `rain_mm_per_hr`, `syn_accident_flag`, `festival_flag`, `zone_type_enc`

Anomaly types classified:
- Sudden traffic spike
- Unexpected traffic drop
- Accident-linked congestion
- Festival-related unusual demand
- Unusual traffic pattern

---

## Evaluation Metrics

All metrics computed on the **held-out chronological test set**. Not on training data.

| Metric | Description |
|---|---|
| MAE | Mean Absolute Error (vehicles/hour) |
| RMSE | Root Mean Squared Error |
| R² | Coefficient of determination (1.0 = perfect) |

Metrics are printed to console and stored in `pipeline_output.json` and the `model_evaluations` database table.

---

## Deliberate Design Choices

1. **No LSTM / deep learning**: The project goal is an explainable, reliable system rather than maximum algorithm count. XGBoost provides feature importance and is well-understood.

2. **No individual tracking**: K-Means is applied to zone-level aggregated demand, not individual vehicle or person trajectories.

3. **Research-grounded synthetic data**: Because no continuous real-time sensor feed is available for Chennai, synthetic data generated from documented behavioural assumptions is used. This is clearly labelled throughout the system.

4. **Reproducibility**: All random processes use `SEED=42`.
